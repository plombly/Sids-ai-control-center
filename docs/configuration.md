# Configuration

Almost everything is set in the dashboard: **Settings** (gear icon). Each
setting says when it takes effect: *at once*, or *after Apply now*, which
restarts LAIka's services safely (running jobs finish first).

Per-project settings (importance, tests, how to run and build the project,
internet access for tests, secrets, GitHub push) are on each project's
**Settings** tab.

## Your account and access

**Settings → Access**: change your password, see and end signed-in
browsers, read the audit log. **Settings → Phones & apps**: pair and revoke
phones. See [Security](security.md).

## AI providers

**Settings → AI & pipeline → Accounts** shows whether Claude and Codex are
signed in. Sign in with your subscription (the page shows a link and a
code) or save API keys (stored root-only on the server, never shown again).

Which AI does what is set per role:

| Role | Default | What it does |
| --- | --- | --- |
| Planner | Claude (Opus) | turns a goal into jobs |
| Builder | Codex | writes the code |
| Reviewer | Claude (Sonnet) | reviews every integrated change |
| Repair | Claude (Sonnet) | fixes what review finds |

When Claude hits a usage limit, LAIka falls back to Codex for 30 minutes.

### Workers

How many jobs run at the same time.

| Setting | Default | Allowed | Applies | Notes |
| --- | --- | --- | --- | --- |
| Automatic scaling | on |  | at once | Add workers when jobs could run in parallel and are waiting, remove them when idle. Off: always run the fixed number below. |
| Fixed number of workers | `8` | 1–32 | at once | Used when automatic scaling is off. Each worker runs one job at a time. |
| Fewest workers | `1` | 1–32 | at once | Automatic scaling never goes below this. |
| Most workers | 0 (suggested) | 0–32 | at once | 0 = suggested from this server: 2 per CPU, about 0.9 GB of memory each, at most 16. |
| Add a worker after jobs wait (minutes) | `3` | 0.5–120 | at once | Only jobs that could start right now count: not ones waiting for other jobs or for the same files. |
| Remove a worker after idling (minutes) | `15` | 1–1440 | at once |  |
| Drain a worker below free memory (%) | `15` | 3–60 | at once | Works in both modes: the newest worker finishes its job and stops; never mid-job. |
| Pause new work below free memory (%) | `7` | 1–50 | at once | No worker starts a new job until memory is back above the drain level. |

| Support workers | `2` | 0–31 | after **Apply now** | Up to this many of the last running workers (one per four) prefer medium and low importance work, so smaller projects keep moving. |

## Files in /etc/laika

These are created by the installer and readable by root only. You rarely
need to touch them.

| File | What |
| --- | --- |
| `laika.env` | install-wide switches; `LAIKA_BUILTIN_PROJECT=0` in normal installs |
| `compose.env` | database names and passwords for the containers |
| `redis.env` | the Redis password |
| `operator.env` | the internal operator token |
| `gitconfig` | git settings shared by LAIka's services |
| `providers/providers.env` | AI API keys saved from the dashboard |
| `notify/notify.env` | Discord webhook / ntfy topic saved from the dashboard |
| `project-env/<id>.env` | each project's secrets |
| `project-keys/<id>/` | each project's GitHub deploy key |

After editing one by hand, run `sudo laika restart`.

## Name and logo

The name and logo are deliberately not dashboard settings. To rebrand a
server, write `/etc/laika/branding.json` and run `sudo laika branding apply`
(see `apps/web/brand/brand.json` for the format).
